# VAL-AGENT-DESIGN-CONTEXT: Runtime design guidance for browser agents

Surface: genuine WebMCP browser runtime, tool metadata, and separate diagnostics.
Needs: secure production preview, `WebMCPTesting`, canonical `DESIGN.md`, and the versioned runtime design-context artifact.
Behavior: `get_design_context` is a read-only tool available at the library and after book open. For `library`, `reader`, and `study`, its response is at most 6,000 UTF-16 code units and returns the current guidance version; active/requested surface; viewport class; safe named/custom-theme summary; bounded style summary; board view; available mutation tools; supported semantic roles and primitives; mutation containment; four to six task-relevant composition/accessibility/user-control invariants; and available reversal actions. Unavailable live fields are explicit rather than invented. Guidance and capability claims come from canonical runtime capability data rather than contradictory hand-written prose. The version is SHA-256 over the exact marked `DESIGN.md` UTF-8 bytes, then one LF byte, then UTF-8 JSON of the capability manifest with recursively lexicographically sorted object keys, array order preserved, and no insignificant whitespace; adding or removing a capability therefore changes it. The response contains no book text, raw custom CSS, notes, study payloads, or other user-authored values and requires no repository or harness-skill access. It says creative palette, typography, shape, and composition changes are unrestricted within supported scopes, distinguishes current EPUB-CSS and native-Study scopes, and truthfully identifies whole-application custom worlds as unavailable until their ADR, declarative schema, and lifecycle contract are implemented. Mutation-tool descriptions direct agents to this tool where relevant; routine one-block calls do not require a version handshake. Reads create no persistent user data. The returned capability guidance declares raw observability separate from Study; removal of the legacy activity UI and its diagnostics replacement is owned by `VAL-AGENT-ACTIVITY-PRESENTATION`.
Evidence: exact `getTools()` names, descriptions, and serialized schemas before and after book open; genuine tool calls for all three surfaces with output-length, version, every required live field, unavailable-state, scope/freedom, and no-book/raw-CSS/user-content assertions; an independent implementation of the canonical serialization and digest; regressions that reject the current false “Undo is not implemented” claim and prove a capability change changes the version; unchanged user storage; no unexpected console/network error or book-content egress.

Fail: A repository skill, copied user prompt, direct handler call, full design-document dump, leaked user-authored value, or false claim that whole-application customization is already supported cannot satisfy runtime discovery.
