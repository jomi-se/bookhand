# VAL-SEARCH-BOOK: Bounded non-mutating lexical retrieval

Surface: ordinary browser UI and genuine WebMCP browser runtime.
Needs: `VAL-INDEX-LIFECYCLE`, `VAL-RANGE-OWNERSHIP`, secure production preview, and `WebMCPTesting`.
Behavior: `search_book` and the ordinary Search surface accept a trimmed query of 1–300 characters containing at least one Unicode letter or number and a result limit from 1–10 (default 5), and reject other bounds. The lexical query takes at most 32 Unicode letter/number runs, quotes each as an FTS5 term, and joins them with `OR`; callers never supply raw FTS syntax. It searches only committed chunks for the open book, orders by BM25 then global chunk order then chunk ID, and returns at most the requested count with exact source excerpts no longer than 1,200 characters plus book ID, section index, section label, start/end CFI, and fingerprint. The excerpt is a verbatim canonical substring of the passage resolved by those CFIs; the fingerprint covers that complete resolved citation passage. Several bounded excerpts may therefore share one larger stable citation envelope when Foliate cannot round-trip a boundary inside an adjacent semantic figure/math run. Every response reports `availability: unavailable | partial | ready` and a separate `outcome: results | no-results`. `unavailable` has no committed chunks and returns no results; `partial` searches only committed chunks and may return either outcome; `ready` searches the completed index and may return either outcome. A failed index reports `partial` only when committed chunks remain queryable, otherwise `unavailable`; its bounded failure remains visible in index status. Executing a search never scans live EPUB content, moves the reader, or changes its selection; preserved mathematical text remains exact. A person can open Search, submit a query, understand unavailable/partial/no-result states, and explicitly activate a cited result to navigate through the existing reader path; on mobile the Search surface then yields back to the book.
Evidence: The manually frozen versioned oracle is `tests/fixtures/search/polish-oracle.json`, bound to SHA-256s of `public/books/calculus-made-easy.epub` and `tests/fixtures/epub/tiny-book.epub`. An intentional fixture change requires a reviewed oracle/hash edit; `npm run fixtures:generate` does not regenerate it. The oracle freezes canonical-text queries, independent source href/fragment provenance, required prose and mathematical substrings, top-k position, citation fields, and the rule that each returned citation resolves through the real reader using its section index and CFIs to exact text containing those substrings with the same fingerprint. `maxRank` is a one-based inclusive position in the returned list. Source href/fragment locate the independent expected passage; they are not production result fields. Results must satisfy the oracle and never cross books. A targeted scan of production indexing/search modules and their executable bundle chunks must prove the oracle queries, required prose/math strings, source href/fragment, and expected ranks are not embedded as search behavior; legitimate fixture bytes, catalog metadata, documentation, and ordinary reader rendering are excluded. The validator also changes at least one non-oracle query and observes corpus-derived results, preventing a lookup table keyed only to frozen queries. In a secure production preview, preserve the ordinary Search flow plus genuine WebMCP registration and invalid, empty, valid, no-result, unavailable, partial, and ready calls; record reader CFI/selection before and after search execution and the deliberate navigation only after result activation. Injected index-failure evidence runs separately in the secure `test-harness` preview through genuine `document.modelContext`; production exclusion is proved independently.
