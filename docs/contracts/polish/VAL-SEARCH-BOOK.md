# VAL-SEARCH-BOOK: Bounded non-mutating lexical retrieval

Surface: genuine WebMCP browser runtime.
Needs: `VAL-INDEX-LIFECYCLE`, `VAL-RANGE-OWNERSHIP`, secure production preview, and `WebMCPTesting`.
Behavior: `search_book` accepts a 1–300 character query and a result limit from 1–10 (default 5), rejects other bounds, searches only the open book, and returns at most the requested count with excerpts no longer than 1,200 characters plus book ID, section label, exact text, start/end CFI, and fingerprint; no-result and unavailable-index results are distinct; a search never moves or selects the reader; math remains faithful.
Evidence: The manually frozen versioned oracle is `tests/fixtures/search/polish-oracle.json`, bound to SHA-256s of `public/books/calculus-made-easy.epub` and `tests/fixtures/epub/tiny-book.epub`. An intentional fixture change requires a reviewed oracle/hash edit; `npm run fixtures:generate` does not regenerate it. The oracle freezes queries, source href/fragment, required exact phrases, top-k position, citation fields, and the rule that returned CFIs resolve to the required phrase. Results must satisfy it and never cross books. A production-source/bundle scan must prove the oracle queries, phrases, book title, source href, and ranking outcomes are absent from indexing/search implementation. Also preserve exact schema/name registration, genuine tool invalid/empty/valid/no-result/failure calls, reader CFI/selection before and after, and oracle provenance.
