# VAL-ACTION-PROVENANCE-UNDO: Durable provenance and item reversal

Surface: browser and storage worker.
Needs: `VAL-STUDY-ID-OWNERSHIP` and persistent study items.
Behavior: Annotation and existing native study-item mutations record user or agent provenance plus an action-group correlation ID; the ID supports tracing related calls but does not promise grouped rendering or grouped Undo. Book import/removal, reader style, board view, and the later study-experience type are outside this contract. Each native study-item create/update returns a receipt with prior and applied state, visible scope, sanitizer/validation warnings, provenance and correlation ID, persistence result, and the exact user-visible Undo, Return to source, and Delete actions. Routine one-block calls remain usable without a design-context version. The interface identifies agent work and offers per-item Undo. Undo of one creation removes that record; Undo of one update restores its immediately prior version; both preserve unrelated work and reject unsafe interleaved-revision restoration. Undo and Delete have distinct visible semantics.
Evidence: Schema/worker round trip for annotations and native items; exact native-item receipt fields; correlated multi-call creation without a group-Undo claim; reload then per-item creation/update Undo traces; interleaved user edit preservation and conflict result; visible provenance and distinct Undo/Return-to-source/Delete copy and results.
