# VAL-SOURCE-EXCERPT-LIFECYCLE: Canonical source meaning survives time

Surface: reader adapter, domain, storage worker, search, and browser.
Needs: `VAL-MATH-PASSAGE`, `VAL-RANGE-OWNERSHIP`, and schema migration support.
Behavior: Source-linked records use a versioned typed excerpt containing book identity, exact range, extraction version, canonical accessible text of at most 32,000 UTF-16 code units, fingerprint, and at most 64 ordered text/math/figure segments of at most 8,000 code units each. A newly supplied source-derived quotation is canonicalized from that excerpt; a user-authored quotation is preserved as authored content and linked to, not overwritten by, refreshed source. During migration, a pre-version excerpt whose exact CFI and book still verify upgrades derived source fields automatically without changing authored text. A resolved excerpt from an older extraction version is reconsidered on read rather than remaining indefinitely current. An unverifiable record keeps its original display text, shows a stale-source state, and offers Retry resolution or Relink—not a Refresh action that cannot succeed. Identical annotation references and quotations remain separate user-owned records under ADR 0004; later presentation may relate them but never silently deletes either. Raw XHTML is never persisted as the repair mechanism. W5 and `VAL-INDEX-LIFECYCLE` own deriving the lexical-index version from this canonical source version and proving complete rebuilds after extraction changes.
Evidence: Source-bearing schema migration and newer-schema refusal fixtures; Chapter XIX automatic derived-data repair, extraction-version refresh, and unresolvable Retry/Relink stale state; authored-text preservation; invented source-derived quotation rejection/canonicalization; ADR 0004 plus a same-range annotation/quotation preservation test; browser persistence/reload trace; no raw renderable EPUB markup in stored excerpts.
